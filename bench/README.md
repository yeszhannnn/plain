# Скорость

Пять программ, каждая написана три раза: на Plain (`.eng`), на C (`.c`) и на Python (`.py`). Алгоритм везде один и тот же.

| Замер | Что нагружает |
|---|---|
| `primes` | решето Эратосфена до 5 000 000: список чисел, циклы |
| `nbody` | 5 000 000 шагов задачи n тел (из Computer Language Benchmarks Game): дробные числа, поля объектов |
| `fib` | числа Фибоначчи рекурсией, `fib(40)`: вызовы функций |
| `words` | 5 000 000 слов из словаря в 10 000 слов считаются в таблице: таблицы и текст |
| `text` | один текст из миллиона чисел, `add n as text to built`: сборка строки |

Запуск:

```bash
bench/run.sh        # лучшее из 3 запусков; bench/run.sh 5 — из пяти
```

Скрипт собирает C через `clang -O2`, Plain через `engc.py build` и печатает лучшее время каждого. Python запускается один раз.

## Результат

Облачный контейнер, clang 18, Python 3.13, `bench/run.sh 5`:

| Замер | C | Plain | Python | Plain / C |
|---|---|---|---|---|
| primes | 0.03 с | 0.12 с | 1.82 с | 4.0 |
| nbody | 0.29 с | 0.29 с | 21.15 с | 1.0 |
| fib | 0.28 с | 0.28 с | 11.28 с | 1.0 |
| words | 0.11 с | 0.19 с | 1.41 с | 1.7 |
| text | 0.05 с | 0.09 с | 0.10 с | 1.8 |

Время на этой машине скачет от запуска к запуску на 20–50 %, поэтому в таблице лучшее из пяти.

`primes` в 4 раза медленнее C, и цель «не хуже 2×» здесь не достигнута. Программа на C хранит решето в массиве байтов (5 МБ), а список чисел в Plain занимает по 8 байт на элемент (40 МБ). Если в C взять массив `long`, C тратит 0.069 с, и разница становится 2.1×. Половина времени Plain уходит на то, чтобы заполнить список из 5 миллионов нулей.

В `words` и `text` Plain создаёт новый текст для каждого `n as text`, а C пишет число в буфер на стеке.

## Что сделано для скорости

- `item N of list` и `set item N of list to ...` компилируются прямо в машинный код: проверка границ и загрузка, без вызова функции. Ветка с ошибкой помечена как редкая.
- Переменные верхнего уровня, которых не касается ни одна функция и ни одно правило бота, живут в регистрах, а не в глобальной памяти.
- `add X to t`, где `t` — переменная с текстом, дописывает текст на месте, как StringBuilder в Java. Как только значение `t` копируется куда-то ещё (в другую переменную, в список, в вызов функции), буфер помечается общим, и следующее дописывание делает копию. Поэтому копии никогда не меняются.
- Программа и рантайм собираются вместе с LTO (`-flto`, `ld.lld`) и `-O3`: функции рантайма встраиваются в код программы.
- Цикл `for every n from A to B` с вычисляемыми границами всегда идёт вверх, и направление известно при компиляции.
